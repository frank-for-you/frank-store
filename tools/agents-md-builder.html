What is AGENTS.md?

AGENTS.md is a plain Markdown file at the root of a repository that briefs AI coding agents the way a README briefs humans: how to build and test, how the repo is laid out, what style to follow, how to open a pull request, and where the boundaries are. Because it is a shared convention rather than one vendor's format, a single file can serve Codex, Cursor, GitHub Copilot, Claude Code, Jules, Aider and OpenClaw. Tools differ in how they discover and merge files, so check your tool's documentation.

AGENTS.md vs CLAUDE.md

CLAUDE.md is read by Claude Code; AGENTS.md is the cross-agent convention. The useful content is the same, so avoid maintaining two diverging copies: keep AGENTS.md as the source of truth and have CLAUDE.md point to it, or use the converter above to derive one from the other. The CLAUDE.md Builder generates both from one form.

What makes a good AGENTS.md

  • Exact, copy-pasteable commands for install, build, test and lint.
  • A short repo map so the agent opens the right files first.
  • Checkable style rules, not slogans like "write clean code".
  • Three-tier boundaries: always do, ask first, never do.
  • Security rules: no secrets in the repo, no edits to generated or production files.
  • Under roughly 300 lines, with links to deeper docs.

Frequently asked questions

What is AGENTS.md?

AGENTS.md is a plain Markdown file in your repository root that tells AI coding agents how to work in the project: build, test and lint commands, code style, repo layout, pull request rules and boundaries. It is a cross-tool convention, read by agents such as Codex, Cursor, GitHub Copilot, Jules, Aider and OpenClaw. Check each tool's documentation for exactly how it loads the file.

How is AGENTS.md different from CLAUDE.md?

CLAUDE.md is the file Claude Code reads. AGENTS.md is the vendor-neutral convention used by many other agents. The content is largely the same: commands, structure, style, boundaries. If you use several tools, keep one as the source of truth and have the other reference it, for example a CLAUDE.md that points at AGENTS.md. Verify in your tool's docs how it handles each file.

What should an AGENTS.md contain?

Exact build, test and lint commands, a short repo layout, code style rules that differ from defaults, PR and commit conventions, security rules, and explicit boundaries split into always do, ask first, and never do. Skip generic advice such as 'write clean code'.

How long should an AGENTS.md be?

Keep it under about 300 lines; 40 to 120 is usually enough. Agents load it into context, so long files dilute the rules that matter. Link to deeper docs instead of pasting them. In a monorepo, put a short AGENTS.md in each package for package-specific rules.

Does this tool upload my AGENTS.md?

No. Building, linting and converting all run in your browser in JavaScript. Nothing you type or paste is sent anywhere and there is no tracking. Only the optional email form for the free Starter Pack sends data, and only the email address.

How is the AGENTS.md score calculated?

The linter checks for runnable commands, a test command, agent boundaries, vague filler phrases, length, standard sections, secrets patterns, git conventions and a repo layout. Each check has a weight out of 100 and failures come with a concrete fix. It is a heuristic for finding gaps, not a guarantee of agent behavior.
